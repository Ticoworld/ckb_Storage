# WO03 economic first principles

## Scope and established boundary

This work starts at WO02 commit `6e6f403129136bb6e0ad1038700ca4c57d378b84` on `wo03-storage-economics`. It preserves the WO01 and WO02 evidence and does not repeat their pool experiment. WO01 measured the current standard lock output at 61 occupied bytes/CKB. WO02 showed that a 1 CKB shared claim can credit an already funded ACP cell, while a fresh standard-shaped cell still needs 61 CKB. That capital remains the user's capacity in a live CKB cell; 60 CKB above a 1 CKB monetary claim is recoverable collateral, not a 60 CKB burn. Fees are separate.

At token prices `$0.01 / $1 / $10`, the 1 CKB principal is `$0.01 / $1 / $10`; a fresh 61 CKB output holds `$0.61 / $61 / $610` total, of which 60 CKB (`$0.60 / $60 / $600`) is additional locked capital. The measured fixture fee is 0.0001 CKB. It is a test value, not a network-wide fee quote. At 5% simple opportunity cost, the extra collateral costs `$0.03 / $3 / $30` per year. Over 10 years this is `$0.30 / $30 / $300`; indefinite ownership has unbounded simple opportunity cost and 60 CKB remains exposed to token-price risk while recoverable only if the user can spend the output.

The consensus implementation computes occupied capacity from serialized output fields and rejects outputs with less capacity; it does not contain a user-selectable rent switch. See pinned CKB source `a4aa1286a45bc1d42c30f6698dc51521c3749b40`, `util/gen-types/src/extension/capacity.rs`, and `verification/src/transaction_verifier.rs`. For the standard lock and empty data, WO01's real validator output is 61 CKB. This is current consensus behavior, not an information-theoretic lower bound: a fork can change accounting, but a script cannot waive the global output check.

RFC 0015 (Final at pinned RFC commit `0c945451c24194f4d34d81195c0159df0a67581a`) frames occupied capacity as a scarce storage right and uses secondary issuance/DAO accounting to reward miners for occupied state while compensating DAO deposits for unoccupied capacity. It motivates the monetary/storage linkage as sustainable cryptoeconomics. That is an explicit protocol design and incentive argument, not a proof that this is the only viable arrangement. Current DAO code computes counted capacity by subtracting occupied capacity before applying the DAO exchange rate. Thus unoccupied capacity has an opportunity return under DAO rules; occupied capacity does not gain that counted-capacity compensation. Primary files and exact pins are indexed in [source provenance](../../evidence/wo03/PRIMARY_SOURCES.md).

## Requirements and accounting vocabulary

For every mechanism, the target is a 1 CKB claim in a new standard-shaped, independently controlled L1 output. An existing ACP cell and a shared/off-chain claim are useful alternatives but do not meet that target. Principal is monetary value the user owns. Additional capital is capacity collateral which remains user's property if the output remains spendable. Fees are consumed. Rent is consumed over time. Opportunity cost is the return forgone on refundable capital; it must not be counted again as rent. State bytes are an ongoing resource obligation to validating nodes, block producers and, separately, archive operators. A monetary amount is not a valid enforceable L1 claim after its only state representation is deleted unless a surviving rule and data path let its owner prove and spend that claim.

Prices are hypothetical USD/CKB values, not forecasts. Durations are 1 year, 10 years and indefinite; indefinite is not replaced by a 100-year proxy. A finite lease which expires while the user is offline fails the direct-control requirement unless the monetary right survives expiry and remains provable. The model's 0.0001 CKB fee is inherited solely to make the fee term visible. A real fee market is variable.

## IF / ELSE / WHY / HOW / WHAT IF

1. **Separate monetary value from storage entitlement.** If 1 CKB no longer carries 1 byte of capacity, new value can fit a standard output with less collateral. Why can old CKB keep its original option while new balances use less? Only with an explicit issuance/conversion boundary and reservation rule. If both old units retain the full old byte right and receive a new cheap balance right, rights are duplicated. If old units are converted, their bundle changes. What if all legacy holders exercise their old rights at once? Reserve against the maximum entitlement, not the currently occupied subset, or define a rationing rule that changes their rights.
2. **Term pricing.** If storage is rented, the initial capital can fall. Rent has to cover future validation/storage costs under uncertain demand and hardware prices. What if a user is offline at renewal, censors are active, or native price crashes? Deletion cannot burn their money; migration/proof data and an exit window have to remain funded and available.
3. **Adaptive bytes per capacity unit.** If hardware improves, conversion could be relaxed; if hardware regresses, it could tighten. Who measures the real resource budget? A feed of hardware prices is manipulable or delayed. Deterministic protocol meters (bytes, state growth, cycles, bandwidth) are observable, but they do not reveal hardware cost or social demand without governance/market choices. What if the parameter rises after users have formed long-lived state?
4. **Demand-priced admission.** If admission auctions allocate a bounded byte budget, users who value state most can pay. It bounds a measured budget only if the budget is a protocol rule and bids cannot be sybil-collapsed or captured by miners. An auction does not preserve a legacy entitlement that must be exercisable regardless of price.
5. **Reclaim unused rights.** If dormant accounts release storage credits, state growth falls. If those credits are only reclaimable while the owner is online, offline security is delegated. If rights expire regardless of liveness, monetary claims can be lost. If never-reused credits are reserved forever, dormant rights do not reduce worst-case capacity.
6. **Protect offline users.** If a receipt lets an offline user reconstruct a claim, somebody must preserve the receipt, root/commitment and data availability. A commitment alone proves no withheld data. If a fixed consensus checkpoint remains, it can prove authorization but still needs account/claim identity and replay protection.
7. **Preserve legacy holders.** If every old CKB remains redeemable into its old capacity right, new issuance must not sell that same right again. Otherwise the protocol has either an unbacked priority claim or dilution. What if token prices diverge from storage demand? The legacy right can be economically valuable even when not currently occupied.
8. **Bound state growth.** If per-user state is made cheaper, demand can rise. Cheap access cannot be evaluated at a fixed small user count only: model sybil demand, mass creation and dormancy. A hard cap with paid priority may bound growth, at the cost of exclusion and congestion rents.
9. **Maintain miner security.** If occupation-linked issuance declines as capacity is decoupled, the protocol must identify replacement security income: issuance, fees, rent, or external endowment return. Each has different dilution, demand and price risks. A storage payment cannot be counted once for nodes and a second time for miners.
10. **Other arrangements.** State channels, account abstraction, archival receipts and off-chain databases can reduce persistent L1 state. They either defer to a funded exit state, add challenge/availability assumptions, or change the requested ownership outcome; they are not a lower-cost fresh L1 cell under unchanged consensus.

## Evidence limits

The simulator is an accounting and sensitivity harness, not an equilibrium model. It explicitly parameterizes a storage cost, replication equivalent, real discount rate and security stress budget because no source establishes a universal future value for those quantities. Results are conditional. Primary consensus evidence establishes the output floor; the economic sustainability of an alternative depends on unmeasured long-run resource and security costs. See [simulation results](SIMULATION_RESULTS.md), [rights analysis](LEGACY_RIGHTS.md), and [security/state growth](SECURITY_AND_STATE_GROWTH.md).
